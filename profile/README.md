<h2>Claude住宅IP断线重连该怎么配：超时、退避与状态恢复的设置顺序</h2>

<p>Claude住宅IP断线重连这个环节，配得好和配得差，体验差别很大。配得差的典型表现是断一次就要人工介入，配得好的表现是断了以后自己恢复，业务层几乎感觉不到。差别不在线路，在配置。</p>

<p>第一件事是把超时设对。超时太短，正常的慢请求会被当成断线，触发大量无谓重连；超时太长，真断线时要等很久才发现。建议按实测的响应时间分位数来定，别凭感觉拍一个数。</p>

<p>第二件事是退避策略。重连不能立刻重试，也不能无限重试。建议用指数退避，第一次等一秒，第二次两秒，逐次翻倍并设上限。这样可以避免线路短暂抖动时被自己的重试打垮。</p>

<p>第三件事是状态恢复。重连成功只是第一步，之前进行到一半的操作要能续上或者干净地放弃。没有这一步，重连成功了业务还是会乱，表现为数据重复或者状态不一致。</p>

<p>第四件事是失败计数。连续失败多少次就判定这条线路不可用，要有个明确阈值。没有阈值的话，程序会一直卡在一条坏线上重试，从外面看起来像整体卡死。</p>

<p>第五件事是切换顺序。一条线路判定不可用之后，切到备用的顺序要固定，别随机挑。固定顺序在排查时能说清当时用的是哪条，随机挑就说不清了。</p>

<p>第六件事是恢复后的观察期。切到备用线路之后，先小流量跑一段，确认稳定再恢复全量。直接全量切过去，备用线路要是有问题，会连着崩两次。</p>

<p>最后是日志。每次断线要记时间、当时的线路、失败原因、重连耗时、以及最终结果。这几个字段在复盘时价值很高，缺了就只能靠回忆，而回忆对细节的保留非常不靠谱。</p>

<p>重连逻辑要能关闭。调试的时候自动重连会掩盖问题，先关掉看清楚原始报错，再打开。</p>
